# 研究闭环与输出

用于多轮深研、长报告及断点继续。借鉴 BettaFish 的分节检索反思、论坛反馈和结构化报告生成，转换为单 agent 工作流；不模拟多个独立研究者。

## 分渠道收集，按问题整合

保留材料渠道：原始文件/当事方陈述、独立报道、图像视频、公开讨论或用户数据库。同一内容经不同渠道转述仍归同一原始来源。搜索接口返回视频标题和摘要不等于看过视频；有数据库工具才使用数据库，不假设存在全平台评论库。

临时提纲每节记录：问题、已有证据ID、暂时结论、反证、待补查询。先完成一轮广度检索，再优先补会改变核心判断的缺口。空结果记为本次检索未找到，不反推出材料不存在。

综合检查记录可保存为 `research-state.md`：

| 问题 | 暂结及证据ID | 冲突/缺口 | 下一步 | 状态 |
|---|---|---|---|---|
| 是否连续多日高热 | 目前仅能证明多日有报道，S01/S04 | 缺少逐日讨论数据 | 查指定日期公开讨论及原始统计 | 未解决 |

只保存可审计的研究决策，不记录隐藏思维链。每轮注明新增证据使哪些结论维持、修改或撤回。不同观点不强求合并；同一缺口补搜仍只出现重复材料时暂停该支线，说明需要什么新材料才能继续。

## 内容与排版解耦

短问答不强制建 JSON。多格式或长报告可在研究目录保存 `report-content.json`，采用轻量结构即可，无需兼容 BettaFish 的完整 Document IR：

```json
{
  "topic": "事件身份",
  "as_of": "带时区截止时间",
  "coverage": ["实际读取的渠道及窗口"],
  "sections": [{
    "id": "findings",
    "title": "能确认什么",
    "claims": [{"text": "待填入研究结论", "type": "unknown", "source_ids": [], "limitations": "证据缺口"}]
  }],
  "charts": []
}
```

`type` 区分事实、当事方主张、争议、未知与推断；每条实质判断附证据ID或明确写为未知。图表另存数据、单位、时间窗口、分母、来源ID与采样局限；缺数据则用时间线或证据表，不能为了视觉效果编数。

渲染前核对：来源ID是否存在、证据是否真的支持该句、日期与统计口径是否一致、旧结论是否已被后续推翻。这是内容验证；JSON 合法或图表能显示并不证明内容真实。

## 交付层次

- 默认：用户可直接阅读的回答；深研实际生成 `report.md`、`report.html` 与来源清单并链接交付；用户明确只要聊天回答时免落盘。
- 深研默认：`report.html`，含摘要、目录、时间线、争议对照、观点与来源；链接可点击，图表有数据说明。不得把外部正文直接拼接为可执行 HTML。
- PDF：用户需要时由已完成报告导出并检查分页；不为普通问答安装整套渲染环境。
- 复用：只改样式从底稿重渲染；事实更新先更新来源与受影响结论，并标新截止时间。不能只把旧报告日期改成今天。

交付时简要说明实际研究覆盖、哪些材料未能取得、输出文件及关键不确定性。结构化底稿和状态记录是研究附件，不替代面向用户的清楚结论。

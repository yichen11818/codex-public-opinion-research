# 研究记录与报告

深研或要求留档时在当前工作区创建 `research/<事件简称>-<日期>/`，不把研究数据存进全局 skill；小型问答保留必要来源即可。

深研默认保存 `report.md`、`report.html` 和 `sources.jsonl` 或 `sources.json`（来源与证据），最终回复提供文件链接；用户明确只要聊天回答时免落盘。按实际需要另存 `timeline.md`（传播和事实节点）；只有实际取得评论且要统计时才保存 `comments.csv`，避免无关身份信息。URL 不保存令牌或签名参数。

来源记录可用下列字段，未知值留空，不编造：

```json
{"id":"S01","url":"https://example.org/article","title":"原始标题","publisher":"发布主体","published_at":null,"accessed_at":"带时区的访问时间","source_type":"original_statement","origin_id":"S01","body_read":true,"claims":[{"text":"有来源的主张","status":"party_claim","supports":[],"contradicts":[]}],"limitations":"仅单方声明，未取得附件"}
```

`origin_id` 归并同稿转载、同一视频与同一通报；独立证据数量按原始链而非URL数计算。`status` 可取 `verified`、`party_claim`、`disputed`、`unknown`；研究者推断写进报告并标记，不伪装成来源内容。

时间线字段：日期（含精度/时区）、节点类型、内容、来源ID、当时可知事实、后续修正。未知小时不补成零点。

评论比例写清去重后分母、剔除条件、多标签是否重叠；编码歧义保留“无法判断”。情绪正负说明相对于谁，“对事故难过”不能计作“反对车企”。

## 报告组织

按请求裁剪：

1. 事件身份、发生时间、研究截止时间。
2. 核心结论及不能确定之处。
3. 关键时间线与证据对照。
4. 谁在讨论、哪些共同利益、持续性依据。
5. 各解释的支持/反对材料及剩余缺口。
6. 来源、抽样方式与覆盖局限。

选题筛选可缩成表：事件、发生日期、已证实传播窗口、不同群体讨论证据、重要性判断、来源。缺乏连续热度数据就写“多日跟进，持续高热未证实”，不强排“年度最爆”。
